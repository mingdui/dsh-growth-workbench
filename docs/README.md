## 先看哪一篇

- **想用**：产品文档 → 第四、九节（用户旅程与后续路线）
- **想改**：架构文档 → 第四节（与 DSH 的接缝）、第八节（扩展点）
- **想判断值不值得投入**：产品蓝图 → 第〇节（赌注）、第六节（瓶颈）

## 三篇之间的关系

```
产品蓝图     说什么值得做，为什么，到哪去
    │
    ▼
产品文档     规则是什么，为什么是这条而不是别的       ← 可以独立读懂
    │
    ▼
架构文档     规则怎么变成不会静默出错的代码
```

**产品文档是唯一的规则真相源在文档侧的落点。** 架构文档写"代码怎么保证"，但它不复述规则本身；两者冲突时以产品文档为准。

新增或修改规则时改产品文档；架构文档只写"代码怎么保证"，不复述规则本身。
