# 二次开发

想在这个项目上做自己的版本 —— 换一套方向、换一条主线、接到别的宿主，或者只是加一个页签 —— 这份文档说清**从哪读、改哪里、什么不能碰**。

## 一、先读顺序

代码分六层，每层只做一件事。**按这个顺序读，比从 `client.js` 开始省一半时间**：

| 顺序 | 文件 | 读它得到什么 |
|---|---|---|
| 1 | `model.mjs` | 领域规则：方向目录、能力模型、权重、加权缺口、完成率、连续打卡、阶段、曲线准入 |
| 2 | `validate.mjs` | 写入门禁：计划与考核到底什么算合法（**这是最像规格说明的一份**） |
| 3 | `store.mjs` | 数据读写：四份 JSON 的字段、原子写、只追加字段的合并规则 |
| 4 | `api.mjs` | 页面的 JSON 路由与状态聚合（`buildState()` 一次给全页面） |
| 5 | `tools.mjs` | Agent 的 7 个工具与它们的简报 |
| 6 | `client.js` | 浏览器半边：左侧整页（四页签）+ 右侧「今日」窄栏 |

**`selftest.mjs` 是最好的规格说明。** 每一条门禁都有对应的反例（"这种计划必须被拒"）。条数以 `npm test` 的输出为准（它会自己报）。改代码前先看它，改完再跑它。

```bash
npm test        # node selftest.mjs —— 不需要 DSH 在跑，不需要浏览器
npm run check   # 逐个文件语法自检
```

## 二、最常见的五种改法

### 1. 加一个方向（岗位）

改 `model.mjs` 一处：往 `ROLES` 里加一份能力模型，往 `DIRECTIONS` 里加一行目录项。

```js
export const ROLES = {
  'my-role': {
    slug: 'my-role', name: '我的方向', status: 'draft',   // draft = 未经行业校准，页面会如实标注
    groups: [ { key: 'A', name: '基础', weight: 60 }, { key: 'B', name: '进阶', weight: 40 } ],
    items: [ /* 8-40 项，每项 { id, group, name, level, anchors: [1分, 3分, 5分] } */ ],
  },
}
```

目录里的档位**不用你写** —— `ROLE_CHOICES` 从 `ROLES` 推出来：有模型就是「预置方向」，没有就是「模型建设中」。

锚点必须是三条**真实刻度**（3 分 = 能照现成规范独立做出合格产出，5 分 = 没有现成可照、自己定标准），不许写「待补」这类占位 —— 校验器会拒。加完跑 `npm test`，它会用同一道校验器核对你的模型。

### 2. 加一条规则（门禁）

改 `validate.mjs`：想清这条规则要拦的是什么失败，把它写成 `problems.push(...)`，消息里给出**怎么改**，然后在 `selftest.mjs` 里加一条反例断言。门禁是纯函数，可以穷举测试。

一条经验：**同一个字段只报一次**。写法错了就不要再报"它指向的东西不存在" —— 一处错被数成两处，用户会以为整份东西都烂了。

### 3. 加一个 Agent 工具

改 `tools.mjs`：加一个普通对象（`name` 用 `growth_` 前缀、`parameters` 写裸 JSON Schema、`execute` 里读写数据），然后登记到 `TOOLS` 与 `TOOL_NAMES`。

两条硬约束：

- **工具是普通对象，不是 `defineTool` 的返回值** —— 宿主半边不许 import 任何 `@deepseek-ai/*`。link 安装时插件真实路径在 profile 的解析根之外，裸 import 解析不到。
- **写入必须走 `validate.mjs`**，不许绕过门禁直接写盘。

工具说明（`description`）常驻模型上下文，所以**契约写在说明里**：要说清什么时候用、写完会发生什么、不许做什么。

### 4. 加一条页面路由

改 `api.mjs`：写在 `handleApi`（读）或 `mutate` 的 `switch`（写）里。页面用 `call(path, body)` 调它，返回 `{ ok: true, ... }`。

- 请求体上限 256 KB；要收更大的**原始字节**（文件），照 `POST /evidence` 的写法单独开一条，并把上限写明。
- 返回给页面的东西经过 `buildState()` 聚合 —— 新数据要加进那里，页面才看得到。
- 二进制响应自己 `writeHead` + `end`，**非图片一律 `application/octet-stream` + `attachment`**：把用户上传的内容按原类型回，就是同源 XSS。

### 5. 改/加页面

改 `client.js`。它是手写的 `React.createElement`（别名 `h`），没有 JSX / TypeScript / 打包步骤，四条规则不要破：

- 必须保持 `window.__ModuleLoader__.load({ id, factory })` 形式；
- **每个 `createElement` 的 children 一律传数组** —— 丢括号不会报错，只会把后半棵树静默挪进错误的父节点；
- 颜色与字号只从 `S` 令牌表取；hover / focus / 动效写在注入的那一段 `.gw-root` 作用域 CSS 里（裸元素选择器会漏进宿主界面）；
- 可点的东西必须有可见的 hover / focus，触控目标 ≥ 44px，并尊重 `prefers-reduced-motion`。

加一个页签：往 `TABS` 加一项、在 `Panel` 的 `bodies` 里给它一个 body。加一个**新座位**（比如第三个面板）：在 `inject` 里声明要用哪些注册表（`slots`、`sidebarRightTabs`、`sidebarRight`），再按现成的两处写法注册。

## 三、不能破的边界

破了这些，页面上的数字就会开始骗人 —— 而它们看起来仍然正常：

| 边界 | 为什么 |
|---|---|
| 页面与 Agent 读写**同一份 JSON** | 页面不得另建 localStorage / 内存真相，否则两边会各说一套 |
| 所有写入过 `validate.mjs` | 门禁是纯函数，能穷举测试；绕过它就等于没有规则 |
| `verifiedFacts` / `pending` / `dismissedTransferable` **只追加** | 未确认的推测不得覆盖已确认的事实；被否掉的不许再回来 |
| 未确认 ≠ 0 分 | 缺数据要显式记 `unsubmitted`，不许补零造出一个假差距 |
| 任务标识一经分配**永不复用** | 存储以它为键，复用会连旧记录一起继承过来 |
| 完成率与证据质量**分开** | 合成一个"真实完成率"就再也说不清差在哪 |
| 宿主半边**零 `@deepseek-ai/*` import** | 见上一节；`selftest.mjs` 有断言守着 |
| **不引运行时依赖** | 图表与徽章都是手写 SVG。加依赖会带来构建步骤与授权问题 |

## 四、改身份（把插件改成你自己的）

插件的身份是**四处逐字一致**，少改一处会**静默不挂载**：

| 位置 | 值 |
|---|---|
| `package.json` 的 `name` | 你的插件名 |
| `cordis.patch.yml` 插入行的 `id` 与 `name` | 同上 |
| `index.mjs` 的 `export const name` | 同上 |
| `client.js` 里 `__ModuleLoader__.load` 的 `id` | 同上 |

改 `cordis.patch.yml` 时注意两条：新行放在 `insert` 下面，**覆盖已有行写在顶层**（把覆盖写进 `insert` 会触发 `duplicate loader entry id`，profile 起不来）；patch 对目标行的 `config` 是**整段替换**，覆盖时要重述该行全部键。

改名后装到自己 profile：

```bash
dsh plugin --profile web add ./你的目录
# 重启 DSH
dsh --profile web --dump-config | grep 你的插件名
```

## 五、换宿主 / 换主线

- **领域层是纯的。** `model.mjs` / `validate.mjs` / `store.mjs` 不 import 任何宿主包，能在普通 `node` 里直接跑（`selftest.mjs` 就是证明）。接别的宿主只需重写三端：`api.mjs`（传输）、`tools.mjs`（工具）、`client.js`（界面）。
- **换一条主线**（比如不做 90 天计划，改做别的周期）：先改 `model.mjs` 的领域规则与 `validate.mjs` 的门禁，再改页面的四个页签 —— 数据层与门禁那一套（原子写、只追加、纯函数校验、反例断言）可以整段留用。
- **数据可以搬。** 全部在 `$DSH_HOME/growth-workbench/` 下，`GET /gw/api/export` 一次导出；`DSH_HOME` 指到别处就是另一个沙箱。

## 六、怎么验你的改动

1. **离线自检**：`npm test`。它是这个仓库唯一随代码发布的验收手段 —— 不需要 DSH 在跑、不需要浏览器。加功能就加断言，尤其是**反例**。
2. **语法**：`npm run check`。
3. **契约**：改过 manifest 后 `dsh --profile web --dump-config`，确认有一层你的插件、且没有 duplicate 告警。
4. **真机**：装 → 重启 → 打开页面走一遍主路径（今日打卡一次并回查 `progress.json`）。

**浏览器级验收脚本不在本仓库里**：它依赖本机排障材料，暂不外发。你需要自己的页面级验收时，无头 Chrome + DevTools Protocol 是够用的路子（`Runtime.evaluate` 取元素坐标、`Page.captureScreenshot` 截图）。
